# AI の使い方ガイド

この授業では AI を積極的に使ってかまいません。ただし「AI が書いたコードを理解せずに動かす」のは危ない(モーターが暴走する)ので、次のルールを守ってください。

## ルール

1. AI が書いたコードは、まず **読んで説明できる** ようにする。わからない行は AI に「この行は何をしているか」を聞く。
2. 実行は `--dry-run` → 車輪を浮かせて → 床に置く、の順。
3. `materials/` は AI にも編集させない。`work/` で作業する。
4. AI の出力をそのままレポートに貼らない。自分の言葉に直す。
5. 班の仲間にも、何を AI に頼んだか共有する(`work/README.md` に書く)。

## ツール別の始め方

AI ツールは自分の PC で動かします(ラズパイ Zero 2 W はメモリが足りません)。

### Claude Code

```
git clone -b group-a https://github.com/ishikuro-lab/seminar2.git
cd seminar2
claude
```

リポジトリの `CLAUDE.md` と `.claude/skills/` を自動で読みます。例:

- 「raspi-gpio スキルを読んで、右に曲がるプログラムを work/ に作って。走行は 2 秒まで」
- 「motor/straight.py を説明して。特に finally の部分」

### Codex CLI / Gemini CLI / GitHub Copilot(VS Code)

同じく clone してリポジトリのフォルダで起動します。`AGENTS.md` を読みます。スキルを使いたいときは「.claude/skills/raspi-gpio/SKILL.md を読んでから」と頼んでください。

### ブラウザの ChatGPT / Gemini

ファイルの中身を貼り付けて質問します。最初に次の文を貼ると、授業のルールを踏まえた答えになります。

```
私は大学 1 年生で、Raspberry Pi Zero 2 W と DRV8833 モータードライバで
ロボットを動かす授業を受けています。Python 3 と lgpio を使います。
配線は A 側が GPIO17/18、B 側が GPIO22/19 です。
安全のため、走行時間に上限を付け、終了時に全ピンを Low にしてください。
初心者向けに日本語で説明してください。
```

そのあとに `motor/motor_test.py` の内容と、やりたいことを貼ります。

## 使えるプロンプトの例

| やりたいこと | 頼み方 |
|---|---|
| コードの理解 | 「このコードを 1 行ずつ日本語で説明して」 |
| 機能の追加 | 「straight.py をもとに、左右の速度を変えてカーブするプログラムを書いて。引数で左右の速度を指定したい」 |
| エラーの解決 | エラー全文を貼って「このエラーの原因と直し方を教えて」 |
| テスト | 「このプログラムを安全に試す手順を順番に書いて」 |
| 振り返り | 「今日やったことを 3 行でまとめて、work/README.md に追記する文を作って」 |

## 気をつけること

- AI は配線やピン番号を間違えることがあります。`motor/README.md` の表と必ず照らし合わせる。
- `sudo` を使うコマンドを提案されたら、実行前に先生に確認する。
- パスワードやトークンを AI に貼らない。
