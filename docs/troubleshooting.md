# 困ったとき(ラズパイ・Git のトラブル対処)

授業中に何かおかしくなったら、このページを上から読んでください。コマンドはそのままコピーして打てます。
ラズパイの画面(HDMI + キーボード)でも、PC から SSH で入った画面でも、やることは同じです。

## 最初の 1 分: どの症状か見分ける

| 症状 | 行き先 |
|---|---|
| PC から `ssh` や `ping` が通らない | [1. PC からつながらない](#1-pc-からつながらない) |
| SSH では入れるが、プログラムや Git がうまくいかない | [2. 入れるけど動かない](#2-入れるけど動かない) |
| 共有フォルダ(`\\groupa.local\自分のユーザー名`)が開けない、保存が固まる | [共有フォルダが開けないとき](#共有フォルダが開けないとき) |
| ラズパイの電源を入れても起動しない、画面が真っ暗 | [3. ラズパイが起動しない](#3-ラズパイが起動しない) |

どれでもないときは [5. 先生に伝えるときの書き方](#5-先生に伝えるときの書き方) を見て、先生を呼んでください。

## 1. PC からつながらない

### まず 30 秒待つ

この授業の Wi-Fi ルーターは、ときどき **つながっているはずのラズパイを忘れる** ことがあります。
ラズパイの画面には `接続済み`(英語表示なら `connected`)と出たままなので、ラズパイ側は気づけません。
PC から送った通信はルーターで捨てられ、`ping` も `ssh` も返事がなくなります。

ラズパイには「見張り」(`wifi-keepalive`)が入っていて、5 秒ごとにルーターへ `ping` を送り、3 回続けて失敗したら Wi-Fi をつなぎ直します。
実際の測定では、切れてから **約 20〜30 秒** で PC から届くようになりました。
なので最初にやることは **30 秒待ってから、PC でもう一度 `ssh` する** ことです。

### 30 秒待っても戻らないとき(ラズパイのキーボードで)

ラズパイにモニターとキーボードをつないで、ログインします(画面に何も出ていなければ Enter を押す。ユーザー名は `seminar2`)。

1. ルーターへ `ping` を打つ。ラズパイが何かを送ると、ルーターが思い出して復帰することがあります。ルーターの IP は授業で先生が伝えます(ここでは例として `192.168.2.1`)。

   ```
   ping -c 3 192.168.2.1
   ```

   `64 bytes from 192.168.2.1` が 3 行出れば OK。PC から `ssh` を試してください。
   別のルーターにつないでいるときは、`ip route | head -1` と打つと `default via 192.168.x.1` のように今のルーターの IP が出ます。

2. だめなら Wi-Fi をつなぎ直す(`sudo` は要りません)。

   ```
   nmcli device disconnect wlan0 && nmcli device connect wlan0
   ```

   `正常にアクティベートされました`(英語表示なら `successfully activated`)と出れば成功。1 回で直らないことがあるので、**2 回まで** 試してください。

3. それでもだめなら、電源を抜いて入れ直す。これは最後の手段です(ラズパイの中の記録が消えて、原因を調べられなくなります)。

### `.local` の名前だけ引けないとき

`ssh sato@groupa.local`(自分のユーザー名と班)が `Could not resolve hostname` で止まるのに、ラズパイ自体は動いていることがあります。
名前のしくみ(mDNS)だけが落ちている状態なので、IP アドレスで入ります。

ラズパイのキーボードで IP を調べる:

```
hostname -I
```

出てきた `192.168.2.xx` を使って、PC から:

```
ssh sato@192.168.2.xx        # sato は自分のユーザー名
```

**班の他の人は名前で入れるのに、自分の PC だけ引けないとき**は、PC のアプリが名前のしくみ(UDP 5353 番)を横取りしていることがあります。ChatGPT のデスクトップアプリで実際に起きました。そのアプリをタスクトレイからも完全に終了してから、もう一度 `ping groupa.local` を試します。

### PC 側を疑うとき

- PC がラズパイと **同じ Wi-Fi**(授業で先生が伝えた SSID)につながっているか確認する。大学の Wi-Fi(eduroam など)につないだままだとラズパイには届きません。
- PC で `ping 192.168.2.1`(ルーター)が返るか確認する。返らなければ PC の Wi-Fi の問題です。

### ラズパイの画面で状態を確かめるコマンド

| 見たいこと | コマンド | 正常なとき |
|---|---|---|
| Wi-Fi につながっているか | `nmcli device status` | `wlan0` が `接続済み`(`connected`) |
| 自分の IP | `hostname -I` | `192.168.2.xx` |
| 今のルーターの IP | `ip route \| head -1` | `default via 192.168.2.1 ...` |
| ルーターへ届くか | `ping -c 3 192.168.2.1` | `64 bytes from ...` が 3 行 |
| 見張りが動いているか | `systemctl is-active wifi-keepalive` | `active` |
| 見張りが何回つなぎ直したか | `journalctl -t wifi-keepalive -b` | `reconnecting wlan0` の行数 |

`systemctl is-active wifi-keepalive` が `inactive` や `failed` なら、先生を呼んでください(再起動に管理者権限が要ります)。

### 共有フォルダが開けないとき

PC から `\\groupa.local\sato`(Mac は `smb://groupa.local/sato`、`sato` は自分のユーザー名)が開けない、または保存が固まるときです。SSH と同じ Wi-Fi を通るので、まず上の「30 秒待つ」と同じです。

| 症状 | 原因 | 対処 |
|---|---|---|
| 開けない、保存が固まる | ルーターがラズパイを忘れた(SSH と同じ) | 30 秒待ってもう一度。だめなら IP で `\\192.168.2.xx\sato`(ラズパイで `hostname -I`) |
| パスワードが違うと言われ続ける(Windows) | 最初に打ち間違えたユーザー名かパスワードが記憶されている | Windows の「資格情報マネージャー」→「Windows 資格情報」で `groupa.local` の項目を削除して、入れ直す |
| 「アクセスが拒否されました」 | 自分以外の名前を開いた、またはアカウントの準備がまだ | アドレスの最後が自分のユーザー名か確かめる。合っていれば先生を呼ぶ |
| Mac で接続が切れた | Wi-Fi の一時断 | Finder のサイドバーで自分のユーザー名の項目を取り出し、⌘K でつなぎ直す |
| SSH も通らない | ラズパイの Wi-Fi | 上の [1. PC からつながらない](#1-pc-からつながらない) |

## 2. 入れるけど動かない

| 症状 | 何が起きているか | 対処 |
|---|---|---|
| `GPIO busy` と出る | 誰かのプログラムが終わらず、ピンをつかんだまま | `ps -o user,pid,cmd -C python3` で持ち主と番号(PID)を見る。自分のものなら `kill <番号>`。班の仲間のものなら本人に `Ctrl + C` を頼む(他の人のプログラムは止められません)。止まらなければ先生を呼ぶ |
| 共有フォルダで保存したのに、動かすと古いまま | 別の班のラズパイを開いている、または自分のフォルダの外を編集した | エクスプローラのアドレス欄の班名と、開いているフォルダが `students\自分のユーザー名` か確認。`ls -l` で更新時刻を見る |
| `git push` が `rejected (fetch first)` | 班の仲間が先に push した | `git pull` してからもう一度 `git push` |
| `git push` が `GH013` で拒否される | `main` に push しようとした(`main` は先生だけ) | `git branch` で確認 → `git checkout group-a`(自分の班に読み替え)→ もう一度 `git push` |
| `git push` で `Permission denied` / `403` | GitHub の認証が切れた、または招待を承諾していない | `gh auth status` で確認 → 切れていれば `gh auth login`。招待メールを承諾したか確認 |
| `Your branch is behind` | 班の仲間が先に push した | `git pull` してから `git push` |
| `CONFLICT` と出た | 同じ場所を別々に直した | [branch-workflow.md](branch-workflow.md) の「衝突したとき」。戻すなら `git merge --abort` |
| `fatal: not a git repository` | 場所が違う | `cd ~/seminar2` |
| `sudo` が必要と言われた | 管理者権限が要る操作 | 受講生は使えません。何をしたかったかを先生に伝える |
| `pip install` が失敗する | システム全体には入れられない | `pip install --user パッケージ名`。`sudo pip` は使わない |

## 3. ラズパイが起動しない

| 画面の様子 | 何が起きているか | 対処 |
|---|---|---|
| `mmc0: Card stuck being busy!` が延々と出る | SD カードを読めていない(カードの不良や相性) | 先生を呼ぶ。カードの交換が要ります |
| 真っ暗で何も出ない | HDMI か電源 | ケーブルを差し直す → 別の電源アダプタを試す → それでもだめなら先生へ |
| 文字が流れたあと `login:` で止まっている | **正常**。起動は終わっています | ユーザー名 `seminar2` でログイン |
| `Reached target cloud-init.target` で止まって見える | **正常**。起動完了の表示 | Enter を押すとログイン画面が出る |

## 4. よくある打ち間違い

- `wlan0` の最後は数字の **ゼロ**(アルファベットの O ではない)。
- `nmcli` は n・m・c・l・i。
- `ping -c 3 ...` の `3` を忘れると `ping: invalid argument` になる。`ping 192.168.2.1` と打って `Ctrl + C` で止めてもよい。
- ラズパイの画面に何も出ないときは、まず Enter を押す。
- PC からの `ping` にラズパイが答えなくても、ラズパイの画面には何も出ない。両側で確かめる。

## 5. 先生に伝えるときの書き方

スクリーンショットより文字のほうが早く解決します。次の 3 つを伝えてください。

```
班: A 班(groupa)
いつから: 10:32 ごろ、git push をした直後
画面の文字: (出ているエラーをそのまま。長ければ最後の 5 行)
```

ラズパイに入れるなら、次の結果も付けると早いです。

```
hostname -I
git branch
git status
```
